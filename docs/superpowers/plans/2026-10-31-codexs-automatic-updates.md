Steps use checkbox (`- [ ]`) syntax for tracking. User Git, installation and manual-observation rules override skill defaults.

**Goal:** Automatically port, validate, publish and install stable Codex CLI updates while retaining the custom footer, existing editor and working installation.

**Architecture:** A trusted hosted controller applies the audited footer overlay to immutable upstream source and runs existing native acceptance plus packaging tests. A separate publisher signs complete release bundles; a Windows launcher stages verified updates in the background and activates them between launches. Immutable installations and transactional state keep old sessions consistent and support recovery.

**Tech Stack:** Existing Rust CI; Node 22+ CommonJS and `node:test`; Node standard-library HTTPS, crypto and filesystem APIs; PowerShell 5.1/.NET ZIP and exclusive-file/replace operations; existing Bun formatter build/tests; GitHub Actions and public Releases. No new runtime npm dependencies or client Git/GitHub CLI requirement.

**Spec:** `docs/superpowers/specs/2026-10-31-codexs-automatic-updates-design.md` (approved 2026-10-31). Read it and the original handoff/design/plan before execution; old acceptance is not evidence for a new native revision.

## Global Constraints

- Windows 11 x64 and PowerShell 5.1 first; Node 22 or newer. Do not silently install prerequisites.
- Check upstream every six hours; client distribution checks at most hourly. No service or scheduled task on the client.
- Automatic routine updates require no prompt after one-time approved enrollment. Activation occurs on a subsequent launch; active sessions are never terminated or rewritten.
- Stable upstream releases only. No failed/missing suites, nightly/prerelease builds, snapshot acceptance, unmodified-CLI fallback or unsupervised agent conflict repair.
- Preserve one Cargo build job, `--release --locked`, LTO off, debug zero, TUI optimization level one, existing guard limits/timeouts, `INSTA_UPDATE=no`, serial full/baseline cases and parallel independent jobs. No local Cargo/Rust execution or agent-run real native binary.
- Signed public bundles from `TK-06/codexs`; match native/helpers/formatter/evidence exactly. Source checkout and official global Codex are independent from client installation.
- Archive limits: 256 MiB compressed, 2 GiB expanded, 10,000 entries; at least 8 GiB free disk. No package lifecycle scripts on the client.
- Keep settings outside immutable release directories. Preserve unknown settings and saved extra lines. No credentials, real payloads/session IDs, personal fixture paths or pending snapshots in commits.
- No official `codex` replacement, global npm write, real `~/.codex/config.toml` change, new metrics, editor redesign or multiline implementation.
- Current-turn explicit authorization is required for every assistant Git/GitHub write. Checkpoints list exact files and suggested commit messages; they are not automatic commits.
- Workflow enablement on `main`, signing-secret provisioning, first publication, enrollment/config/shims/PATH and actual visual checks retain concrete approval/observation gates. Product no-prompt behavior does not override these setup gates.

## Review Focus

1. Paths/arguments containing spaces, Unicode, `%`, `!` and quotes must preserve cwd/arguments without shell evaluation; Task 8 pins both managed shims.
2. Concurrent terminals and a crash during activation must never mix native/helpers/formatter or lose both pointers; Task 6 pins filesystem replacement and Task 8 pins process lifetime.
3. A changed upstream package layout or a renamed/empty test filter must block distribution rather than certify an incomplete build; Tasks 1, 3 and 10 pin these conditions.
4. Offline/rate-limited networking, clock rollback and low disk must leave normal launch available without a prompt or retry storm; Tasks 5 and 7 pin these conditions.
5. Shared upstream user-data changes and arbitrary nonzero native exits must not cause settings restoration or automatic conversation replay; Tasks 7, 8 and 12 pin the recovery boundary.

## Shared contracts

All Node modules are CommonJS with no import-time I/O. Invalid input throws an error named `UpdateError` with a bounded stable `code` and no sensitive path/payload in its public message. The hosted upstream module owns its small error class independently of the later client protocol class; cross-boundary consumers use `code`, not constructor identity. Tests use `node:assert/strict`, `node:test`, ephemeral keys and owned temp roots; no global module mocks. Commands below run from the Codex repository with Node 22+.

`Release` schema 1 has exactly: `schema`, `repository`, `channel`, `sequence`, `release_id`, `product_version`, `upstream` (`version`,`tag`,`sha`), `native_sha`, `overlay_sha`, `formatter` (`sha`,`version`), `target`, `bootstrap_min`, `node_min`, `archive` (`name`,`bytes`,`sha256`), `files` (sorted `{path,bytes,sha256}` array), `packages` (`main`,`helper`, each `{name,version,integrity}`), and `evidence` (Task 9 contract). Repository is `TK-06/codexs`, channel `stable`, target `x86_64-pc-windows-msvc`, `bootstrap_min=1`, `node_min=22`. Product/upstream/formatter versions use strict stable SemVer; the helper package's version must instead match its verified platform-alias form. IDs match `codexs-v<product>-codex<upstream>-r<sequence>`; sequence is a positive safe integer and all source SHAs are 40 lowercase hex characters. Require `evidence.candidate_sha == native_sha`, `evidence.upstream_sha == upstream.sha` and `evidence.formatter_sha == formatter.sha`.

Sign `Buffer.concat([Buffer.from('codexs-release-v1\0','utf8'), manifestBytes])` with Ed25519. Manifest is UTF-8 without BOM or trailing newline, recursively sorted object keys, sorted inventory paths, integer numbers, no duplicate/unknown fields. Signature sidecar is exactly 64 raw bytes. Reject noncanonical bytes even when signed. Cap manifest at 4 MiB. The ZIP does not contain itself, `release.json` or its signature: store those validated sidecars separately under each immutable installation; their names are reserved and not payload entries.

`State` schema 1 in `current.json` contains `current`, `previous`, `ready` (nullable `ReleaseRef`), `highest` (nullable `{sequence,manifest_sha256}`), `rejected` (release IDs), `last_check_ms`, `next_check_ms`, `failures`. `ReleaseRef={release_id,sequence,manifest_sha256}` resolves only inside `versions/<release_id>`. No absolute path or executable command comes from a feed. Local bootstrap configuration holds the explicitly installed Node/settings paths and pinned public key; neither is overwritten by routine updates. Limit state to 4 MiB; invalid state uses a validated backup, otherwise fail with recovery instructions, never pick an arbitrary version directory.

Coordinator requests have exactly `mode` (`check`,`promote`,`rollback`,`commit-state`), `root` and validated mode-specific data. Production callers derive root from the installed launcher; arbitrary root/feed/key injection is test-module-only. `coordinator.ps1` opens `update.lock` with `FileShare.None`, attempts immediately, and holds it through the child worker; process death releases it. Never delete a lock based on PID/age. `commit-state` runs only as an internal operation under that lock, writing/flushing a same-volume temporary, then `[IO.File]::Replace` with `current.previous.json` backup; initial creation uses `[IO.File]::Move`. Do not reacquire the lock recursively.
